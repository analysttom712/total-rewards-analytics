# Day 005: A test that passes isn't proof until you've watched it fail

*Draft by Claude. Thomas edits before posting.*

## Portfolio post

**What I worked on**

Every census file I've ever handled gets the same two checks before anyone trusts it: no duplicate employee IDs, and nobody paid outside their pay band. Today I wrote those two checks as automated tests for my fake-employee generator (fictional company, Faker data), so they run every time the code changes instead of whenever I remember.

**What I learned**

Duplicate IDs turned out to be one line. A Python `set` keeps only distinct values, so if any ID repeats, the set is shorter than the list:

```python
assert len(ids) == len(set(ids))
```

That's `DISTINCTCOUNT(id) = COUNTROWS(table)` from DAX, nearly word for word.

The pay-band check means joining each employee to the job catalog on `job_code`, then checking the salary falls between the band's minimum and maximum. Python lets you write that like SQL's `BETWEEN`:

```python
for e in employees:
    for job in JOBS:
        if job["job_code"] == e["job_code"]:
            assert job["salary_min"] <= e["salary"] <= job["salary_max"]
```

**What was hard**

That second test took me four tries, and the first one is the lesson I'll keep. I joined on the wrong field, a job *title* compared against a job *code*. Nothing ever matched, so the `assert` never ran, and pytest said **passed**. That's a Power Query merge that matches zero rows: the exceptions tab comes back empty, which looks like a clean tie-out but checked nobody.

So I didn't trust the test until I'd watched it fail. I planted a bug in the generator that could pay people up to $50,000 over their band's max, ran the tests, and got:

```text
assert 155302 <= 125000
```

Employee 100002 was paid 155,302, over the 125,000 max for a Compensation Analyst. Then I took the bug out and it went back to green. My first idea for the planted bug (raising the band's minimum) wouldn't have worked: the generator reads that same band, so both sides moved together. A check can only catch a mistake that one side makes.

Smaller lessons: an editor tab with unsaved changes is invisible to Git, and `git commit --amend` fixes a bad commit message, as long as you haven't pushed yet.
