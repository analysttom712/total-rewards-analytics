# Day 006: Run it "as of" a date, or it won't tie out

*Draft by Claude. Thomas edits before posting.*

## Portfolio post

**What I worked on**

Every HR or payroll report I've signed off on is run *as of* a date: headcount as of 10/31, the register for the pay period ending the 15th. Run it again next month and it still ties, because nothing in it depends on the day you click Refresh.

My fake-employee generator (a fictional company, Faker data) didn't work that way. It drew hire dates from "the last 10 years, up to today". Same code, same random seed, and employee 100001's hire date still moved from 2020-09-10 to 2020-09-13 over two days. Today's ticket was to pin it.

**What I learned**

The fix is two constants at the top of the file, the same idea as a "Period end" parameter on a report's cover page:

```python
from datetime import date

AS_OF = date(2026, 11, 1)
EARLIEST_HIRE = date(2016, 11, 1)

hire_date = fake.date_between(start_date=EARLIEST_HIRE, end_date=AS_OF)
```

Then a **golden-value test**: I typed the expected answer in by hand, so if anything makes the output drift, the test fails loudly.

```python
def test_first_hire_date_is_pinned():
    first = build_employees(1)[0]
    assert first["hire_date"] == date(2020, 8, 18)
```

To prove the whole file stopped changing, I used `Get-FileHash`, a fingerprint of the file's exact bytes. Two runs, same hash.

**What was hard**

The test took three tries. I wrote the dict key without quotes (`NameError`), then used the constant's name as the key, then fixed a slice (`[1:25]`) that returned a list instead of one employee.

Breaking it on purpose taught me the most. Claude's first suggested break, sliding only the *end* of the window, didn't fail the test at all, and I ran it and said so. It turns out the library builds a date as *window start + a random offset*, so the start sliding was the real bug. The end protects a different rule (nobody hired after the as-of date), and that's now its own ticket.

I also got ahead of myself and started adding termination dates. Claude walked me through why that's a separate design (most employees aren't terminated), so I pulled it out.

Last surprise: the tests pass on my Windows machine but fail in GitHub's Linux CI, which draws a different date for the same seed. That's exactly the "same answer anywhere" problem this ticket is about, so tracking it down is next.
